# 电路板结构简化

用户的默认偏好是：主要接口及体积最大的若干元件保留真实形状，其余小元件简化，用于结构装配和空间避让。不要先把全部精细实体融合再导出；装配实例展开会让文件明显变大。

## 处理规则

- 原文件保持不变。输出使用新文件名。默认保留原板形、厚度、安装孔、槽及切口。
- 根据实例名和模型名识别 USB、HDMI、FPC/FFC、插座、排针、端子、射频接口、开关及结构固定件；不把它们仅凭体积小就简化。
- 在上述类别之外默认保留净实体体积最大的 5 个元件；数量可按用户要求调整。每个物理元件作为一组，不能把它的引脚单独参加排名。不要沿用上一个文件的元件序号或世界坐标。
- 其余元件采用其**定义局部坐标**中的包络块，再应用完整装配变换。保留位置、朝向、外形尺寸和最高点，省略引脚、倒角、内部空腔及装饰。包络是保守的避让近似，并非制造模型。
- 无名元件可能包含接口，先保留并检查。未知无厚度曲面、分组不清或多块板，不自动忽略或简化整块装配。已明确识别的无厚度丝印/铜层可以从实体版中去除，并在报告中记载。
- 仅在需要单实体时融合。用户已接受为这类简化模型增加最小连接；默认连接半径 0.03 mm、跨隙最多 0.2 mm，仅用于最近接触处，逐项记录。更大的间隙、改变接口开口或安装孔需另外判断，不用加大整体公差或任意填充来强行连接。
- 默认输出毫米单位 STEP AP214；提供保留/简化清单、实体数、有效性、面数和文件大小。面数和文件大小都是控制指标，不能只看实体数量。若保护项仍导致文件很大，说明原因，不悄悄牺牲接口或大元件。

## 可执行流程

使用 `scripts/pcb_simplify.py`，先分析再构建。它需要 Python 3.12 和已测试的 `cadquery-ocp==7.8.1.1.post1`、`vtk==9.3.1`。可用现有运行环境，或仅安装到当前任务的 `work/cadlibs`，通过 `--ocp-path` 指定。不要依赖历史聊天工作目录。依赖安装示例：

```text
python -m pip install --target work/cadlibs cadquery-ocp==7.8.1.1.post1 vtk==9.3.1 --no-deps
python <skill>/scripts/pcb_simplify.py --ocp-path work/cadlibs analyze input.step --work work/pcb --keep-largest 5
python <skill>/scripts/pcb_simplify.py --ocp-path work/cadlibs build --work work/pcb --output outputs/pcb_light.stp
```

分析保存 `plan.json`、元件 BREP 缓存和输入 SHA-256。**构建前查看 `plan.json` 的名称、保护理由和待检查项**，尤其接口与大元件名单。必要时编辑各元件的 `action`（`keep`、`envelope`、`omit`）及 `review`；处理完待检查项后才能构建。板体始终 `keep`，任何有体积的元件均不得直接 `omit`。可用 `--keep-pattern` 追加保护名称，`--board-pattern` 指定板体；默认自动识别。Windows 中文日志建议启用 `PYTHONUTF8=1`。

脚本支持常见 STEP 装配树及其变换；它有意拒绝只有一个扁平实体、无法可靠识别板体或含待检查项的输入。此时检查源模型，采用适配方法，不要将错误当作用户文件一定损坏。

构建会做布尔融合、小间隙连接、有限几何修复、STEP 导出与回读，断言一个有效实体、无独立曲面以及导出前后体积和外形一致。默认通过 OCCT 官方导出选项省略冗余的曲面参数曲线，保留三维边界与实体，进一步缩小文件；不手改 STEP 实体编号。若这种导出在回读或目标软件中出现问题，用新输出路径加 `--pcurves` 重试一次完整曲线版。检查 `report.json` 的新增连接和修复体积变化；检查预览，确认板的孔槽和接口没有被填平。不能将内核检查通过等同于 SolidWorks 兼容性通过。

## SolidWorks 验证与交付

如果用户要求能在 SolidWorks 中工作，实际导入候选模型，看到模型后检查实体/曲面数量，并保存原生 SLDPRT，再重新打开核验。保留用户其他未保存文档。使用当前会话支持的电脑控制工具及其规则；用户停止电脑控制后立即遵守停止要求。

只在实际成功后说“SolidWorks 已打开验证”。否则明确区分“轻量文件已生成并通过几何校验”和“尚未完成 SolidWorks 实测”。不要承诺所有电路板可安全/稳定打开，也不要因导入耗时就直接宣称损坏。参考本次实测基线见 `references/validation.md`；其中的模型仅验证算法，不是对所有 CAD 文件的保证。
