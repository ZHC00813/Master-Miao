# V1.2.6 变更与开发决策 / Changes and development decisions

0905-R2 更新：定位使用实时文档身份，不再按导出规则访问磁盘或检查待保存标志；去重勾选立即折叠，导出前逐成员做几何重合检查。下文的“先人工确认”是 R1 历史策略，R2 已替换。详见 [R2_FIX_VALIDATION.md](R2_FIX_VALIDATION.md)。

0905-R2 update: live-document locating no longer hashes disk files or rejects pending-save state; the dedup checkbox folds rows immediately, with per-member solid congruence required before export. Human-confirmation-first statements below describe the superseded R1 policy. See the linked R2 record.

## 中文

本次以用户提供的 V1.2.5 为基线，目标是修复输入中断、身份误匹配、状态误报和保存风险，而不是继续叠加外围功能。需求来自实际多实体分类与生产文件交付流程。

### P0：输入与实体身份

- 自动保存不再调用会结束编辑的 `CommitGrid`；仅从已提交模型创建快照。列表不再逐行把陈旧单元格覆盖回模型。逐项名称、分类和勾选一次提交，实际“保存并下一个/上一个”按钮回归会跨越自动保存周期并核对最终项目 JSON。
- 列表改名由独立输入法安全编辑框处理，Enter 明确作为输入键且不提交或退出；编辑按实体引用保存，不依赖刷新后可能失效的行号。模拟输入、明确提交、Esc、已保存/未保存场景均有回归；真实输入法候选窗仍需人工验收。
- 读取恢复 V1.2.5 的线性工作方式：工作进程只接收源文件身份，不再对历史实体执行嵌套 COM 匹配；扫描后的名称、分类和选择在界面进程按索引与几何指纹 O(n) 恢复。SolidWorks 自动重建产生的保存标志只在读取时告警，正式导出仍严格拒绝不确定状态。
- 源文件保存 SHA-256、配置和实体持久引用。定位、导出和重新绑定要求可信身份。重新读取恢复编辑沿用 V1.2.5 的索引加几何指纹规则；正式导出会另行核对持久引用和位置相关几何证据。

### P1：判断、保存和输出可靠性

- 几何指纹降级为候选信号，重复合并需要明确人工确认；支持成员查看、排除、解组、数量及所有来源记录。材料和制造属性没有被冒充为几何判断的一部分。
- 所有导出设置实时进入项目；每个任务冻结自己的请求、选项、分类路径和报表数据。装配体与仅导出一个重复件立即互斥。
- 工作项目 schema 3；相对预览路径，旧绝对路径迁移；预览内容寻址且不覆盖旧资产。保存使用独占锁、并发变更检查、原子 JSON 替换和备份，失败不清除脏状态。
- 按实例/项目隔离恢复记录；主 JSON 损坏时可回退备份。跨目录搬移项目不需要原预览缓存；重新绑定源文件必须验证内容摘要。
- 最终输出统一规划名称，考虑零件、装配体、镜像目录和同批冲突。原文件路径不得成为输出目标。跳过的旧文件标记“未验证”，不算本次成功。
- SLDPRT 重新打开后做几何校验；STEP 重新导入后做实体数、尺度、几何和位置校验。只有校验通过才提交；STEP 失败不销毁已经有效的 SLDPRT。
- 每件结果写检查点，异常后保留完整任务清单。取消请求贯穿宏与工作进程的安全边界，不能立即返回的同步调用有等待说明。仅重试失败项仍执行身份与依赖检查。

### P2：可用性与维护成本

- 报表图片保持宽高比，25 列记录实际/计划名称、路径、数量、来源、逐格式状态和验证结果。冻结表头、自动筛选、数值数量、缺失预览占位，中英文对应。
- 紧凑模式、三视图模式、筛选、搜索、批量命名预览、撤销，以及目录循环和同级冲突防护。
- 缩略图缓存有边界并释放资源；保存移到后台。构建支持 `-SolidWorksApiPath` 或 `MASTER_MIAO_SW_API`；只新增存储、完整性与界面工作流三个有明确职责的文件，不引入新框架。
- 提供源码、测试源码、构建脚本、双语开发说明和明确区分“通过/失败/未执行”的验收记录。原始 CAD 与私人运行数据不随包分发。

### 有意保留的安全限制

新打开的文件也可能因 SolidWorks 自动重建而带有保存标志。读取阶段允许用户先查看和分类并显示警告；仅凭 `GetSaveFlag` 仍无法证明其内存几何等于磁盘状态，因此正式导出会拒绝该状态，且程序不会偷偷清除标志或保存用户文件。导出前应在 SolidWorks 中自行确认并保存，再重新读取；生产验收应使用独立副本。

几何去重采用人工确认路径，不承诺自动识别所有旋转、镜像和特征差异。真实 CAD 极端反例、输入法候选窗、多机多版本和故障注入覆盖度详见验收表，不用合成数据的界面通过代替真实几何通过。

## English

This update starts from the supplied V1.2.5 baseline and prioritizes interrupted editing, ambiguous body identity, misleading results and persistence hazards over adding peripheral features. Requirements come from real multi-body classification and production handoff.

### P0: Editing and identity

- Autosave snapshots committed model state without calling edit-ending `CommitGrid`. Stale grid rows no longer overwrite the model. Guided name, category and selection commit together; actual Save-and-next/Previous button regression crosses an autosave interval and verifies the saved JSON.
- A dedicated IME-safe list editor owns Enter without committing or closing and commits by stable body reference rather than a refresh-sensitive row index. Continuous input, explicit commit, Esc and saved/unsaved states are covered; native IME candidate-window acceptance is separate.
- Scanning again follows the linear V1.2.5 workflow. Only source identity is sent to the worker; an O(n) UI pass restores unchanged body edits instead of nested COM matching. A dirty flag caused by automatic rebuilding is a scan warning, while export remains fail-closed.
- Source SHA-256, configuration and persistent references protect locating, export and rebinding. Restoring rescan edits follows the V1.2.5 index-plus-fingerprint rule; export separately verifies persistent identity and position-sensitive geometry evidence.

### P1: Reliable decisions, persistence and export

- Fingerprints indicate possible duplicates only. Explicit human confirmation enables grouping, with member review, exclusion, dissolution, quantities and all occurrences. Material and manufacturing attributes are not inferred.
- Options immediately update the project. Each task freezes its request, paths, settings and report inputs. In-place assemblies and one-per-group export are mutually exclusive.
- Schema 3 uses relative, immutable content-addressed previews and legacy migration. Exclusive locking, stale-write detection, atomic JSON replacement and backups preserve previous work; failures retain dirty state.
- Recovery is isolated per instance/project. Corrupt primary JSON can fall back to backup. Moved projects retain previews; source rebinding requires a matching content digest.
- Global naming includes native files, STEP mirrors, assemblies and intra-batch collisions. Source targets are forbidden. Skipped old files remain unverified rather than counting as current successes.
- SLDPRT is reopened and checked; STEP is reimported for body count, scale, geometry and placement verification. Valid native parts survive STEP failure.
- Item checkpoints retain complete outcomes after errors. Cancellation is observed at safe worker/macro boundaries, with honest waiting during synchronous calls. Failed-only retries still validate identities and dependencies.

### P2: Usability and maintainability

- Reports preserve image proportions and include 25 columns covering actual/planned names, paths, numeric quantities, occurrences and per-format verification. Bilingual headers, freeze panes, filters and missing-preview placeholders are included.
- Compact/three-view lists, filtering, search, batch naming preview, undo and folder cycle/collision protection improve classification.
- Bounded thumbnail caching and background saves address resource use. API paths are configurable at build time. Three focused helper files separate persistence, integrity and UI workflows without introducing another framework.
- Source, tests, build scripts, bilingual documentation and explicit passed/failed/not-run evidence accompany the package. Private models and runtime data do not.

### Intentional limitations

A freshly opened document may be marked dirty by SolidWorks rebuilding. Scan permits inspection and classification with a warning, but a dirty flag cannot establish disk/memory equivalence, so export rejects it. The application never clears the flag or saves the user's model. Confirm and save it yourself, rescan, and use a separate copy for acceptance.

Deduplication follows an explicit human-confirmation path, not a promise to automatically classify every rotated, mirrored or feature-different part. Native IME, difficult CAD counterexamples, multi-version operation and fault-injection coverage are documented separately; synthetic UI checks are not geometry acceptance.
